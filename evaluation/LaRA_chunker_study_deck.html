The hybrid searcher re-embeds nodes itself (VectorStoreIndex(nodes, embed_model=…) in simpleHybridSearcher.py), so the new chunking adapter only has to produce plain text nodes — it does not need to embed anything. That is why swapping the chunker is a genuinely isolated change: BM25, vector fusion, reranking, and generation see the exact same code path regardless of which chunker produced the nodes.

The 5 chunking strategies
What each one actually does
1 · Token

Token

Splits on a fixed character/token count, no regard for sentence or paragraph boundaries. The simplest possible baseline — closest in spirit to LaRA's original splitter.

chunk_size=600, overlap=100
2 · Sentence

Sentence

Splits on sentence boundaries (. ! ? \n), then packs whole sentences into a chunk up to the size cap. Never cuts a sentence in half.

chunk_size=600, overlap=100
3 · Recursive

Recursive

Tries paragraph breaks first, then sentence punctuation, then clause punctuation, then whitespace — falling back a level only when a piece is still too big. No overlap parameter.

chunk_size=600
4 · Semantic

Semantic

Embeds sentences (model2vec potion-base-32M) and splits where topic similarity drops — chunk boundaries follow meaning, not fixed size. No overlap parameter.

chunk_size=600 (cap)
5 · Fast

Fast

Chonkie's speed-optimized splitter — simple delimiter search with no tokenizer call per candidate boundary. Built for throughput over precision. No overlap parameter.

chunk_size=600
chunk_size held at 600 (characters) for all 5, matching LaRA's original splitter, so the comparison isolates strategy, not chunk granularity. Recursive/Semantic/Fast not having an overlap knob is a real property of those strategies in Chonkie, not an oversight in this implementation.

Code — the adapter
chunkers.py — the entire seam
def _build_chunker(strategy, chunk_size=600, chunk_overlap=100): if strategy == "token": # fixed-size, no boundary awareness return TokenChunker(chunk_size=chunk_size, chunk_overlap=chunk_overlap) if strategy == "sentence": # packs whole sentences to the size cap return SentenceChunker(chunk_size=chunk_size, chunk_overlap=chunk_overlap) if strategy == "recursive": # paragraph → sentence → clause → whitespace return RecursiveChunker(chunk_size=chunk_size) if strategy == "semantic": # splits where embedding similarity drops return SemanticChunker(chunk_size=chunk_size) if strategy == "fast": # delimiter search, no tokenizer per boundary return FastChunker(chunk_size=chunk_size) def get_nodes(text, strategy, chunk_size=600, chunk_overlap=100): chunker = _build_chunker(strategy, chunk_size, chunk_overlap) chunks = chunker(text) # run the actual Chonkie chunker return [TextNode(text=c.text) for c in chunks] # -> LaRA's own node type
One function, one signature, all 5 strategies swappable through the same call — exactly as specified in the ask. Nodes carry only .text; embeddings are computed downstream by the existing hybrid searcher.

Scoring — scale 1
Binary judge: True / False
LaRA's original judge (compute_score_llm.py). One LLM call per question, forced to a single word.
prompt = f"""I will provide you with a question and its groundtruth answer, as well as an answer from an AI assistant. You need to judge whether the AI assistant's answer is correct based on the groundtruth answer. If it is correct, you should only output True; if it is incorrect, only output False.""" … if 'true' in response.lower(): return 1.0 else: return 0.0
Deliberately kept unchanged for this task — it's what the LaRA paper reports, so it stays comparable to published numbers. Its weakness (documented separately for the professor's other ask): a correct-but-reworded answer often reads as "False" to a strict judge, collapsing partial credit to zero.

Why both scales — a real example
Same answer, same judge model, two verdicts
Question (reasoning · book · sentence chunker)

What lesson does Hartman learn from observing Brimstone's Christmas Eve party?

Groundtruth

Brimstone's generosity comes from simple gestures, not money; employers can make employees' lives joyful or miserable at low material cost.

Model's answer

“Hartman learns the importance of making an effort for others and participating in community traditions, as evidenced by Brimstone's enthusiastic celebration…”

Numeric judge's own reasoning

“Mentions participation in community traditions but misses the key point about simple gestures and employer influence.”

False
binary judge (0.0)
4 / 10
numeric judge — partial credit
The binary judge can only say the answer is wrong. The numeric judge says why it's wrong and how wrong — it captured the general shape of the answer but missed the specific lesson. That distinction is invisible on a 0/1 scale and is exactly the partial-credit signal the professor asked for.

Experiment setup
Scope of this run

Fixed across all cells

  • Generator: qwen2.5:7b · Judge: qwen2.5:14b (decoupled, via Ollama)
  • Context length: 32k only (chunking behavior is what's under test, not long-context capacity)
  • chunk_size=600 / overlap=100 (where applicable), held constant across all 5 strategies
  • Retrieval: hybrid vector+BM25, top-5 after rerank — identical for every chunker

Varied

  • 5 chunkers: token, sentence, recursive, semantic, fast
  • 3 doc types: book, financial, paper
  • 4 task types: location, reasoning, comp, hallu
  • 5 questions per (doc type × task type) cell — a bounded first pass, not the full 2,326-question benchmark
60 unique questions × 5 chunkers = 300 generations, judged twice (binary + numeric) = 600 judge calls. ~38 minutes end to end.

Interpretation
Three takeaways
1
Token chunking ranks first on both scales (63.3 binary / 68.3 numeric overall) in this bounded run — the simplest strategy, not the most sophisticated one, retrieved the most useful context for the LLM.
2
Fast chunking ranks last on binary but not on numeric (53.3 vs 63.2) — the same judge-collapse problem already flagged for the professor's other ask shows up again here, strategy-to-strategy, not just model-to-model.
3
Differences between strategies (53–63% binary, 62–68% numeric) are real but not large at this sample size — enough to show the machinery works and to motivate a wider run, not enough to declare a definitive winner yet.

Limitations & caveats
What this run does and doesn't show

Scope limits

  • n=5 questions per cell (60 unique questions total) — a bounded first pass, chosen to fit a "this week" turnaround, not the full 2,326-question benchmark.
  • 32k only — no long-context comparison in this run.
  • chunk_size held at 600 for comparability; a chunk-size sweep per strategy is a natural follow-up.

The numeric scale isn't perfect either

  • Example from this run (fast/comp): an answer that misattributed a character name still scored 7/10 → "True" at the default threshold — the judge rewarded overall shape over one factual error.
  • Threshold=7 for the derived binary is a choice, not a law; different thresholds shift which strategies look best.
  • Both scales share the same underlying judge model (qwen2.5:14b) — agreement between scales bounds internal consistency, not ground-truth correctness.
